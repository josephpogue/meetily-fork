# Changes from upstream Meetily

Every way this fork differs from upstream Meetily ([Zackriya-Solutions/meetily](https://github.com/Zackriya-Solutions/meetily)), built or planned.
The goal, stories and requirements are in `docs/GOAL.md`. Update this file in the same PR as any change from upstream.

**Upstream base:** v0.4.1 (merged in PR #3). Upstream's newest release on 2026-10-13 is also v0.4.1.

## Features

| Feature | What it does | Status |
|---|---|---|
| Assistant panel | A panel beside the live transcript that holds the assistant's answer cards, with an on/off switch and a collapse toggle. | Built (PR #1) |
| Answer help | When someone on the call asks Joseph a question, the assistant suggests an answer from the transcript and the meeting brief. A quick answer appears first, then a fuller check settles it and marks any correction. | Built (PR #1) |
| Answer modes | Manual never volunteers, Gated (default) answers when Joseph is named or after a pause, Continuous answers any question from the room. Opt-M cycles them. | Built (PR #1) |
| Ask | Joseph types a question, or speaks one with opt-A, and gets an answer that uses the call so far. | Built (PR #1) |
| Explain and Catch-up | Opt-E explains what was just said; opt-C summarises the call so far. | Built (PR #1) |
| Meeting note | After recording stops, the assistant drafts a note and a full transcript. They go to the vault only when Save is pressed. Meetily's own meeting save still happens. | Built (PR #1) |
| Assistant settings | A new Assistant tab in Settings: models, answer mode, Joseph's names, vault folder, and a Test claude button. | Built (PR #1) |
| You / Them labels | Each live transcript line is marked as Joseph's mic (You) or the call audio (Them). | Built (PR #1): live view only, not in the saved meeting |
| Meeting brief | An optional typed brief that tells the assistant the point of the call. It stays visible for the whole call and changes only when Joseph presses Save (or Cmd+Enter); an Unsaved marker shows edits not yet sent. A new recording starts clean: the last call's brief, Say cards, questions and to-dos do not carry over, and only a brief typed after Stop and before recording opens the next call. | Built (PR #1); Save button and mid-call edits in PR #6 |
| Brief editable during the call | A saved change to the brief mid-call reaches the answer lanes and Ask next on their next turn. | Built (PR #6) |
| Point of the call from the conversation | The assistant works out what the call is for from what is said, alongside the brief, and works from that when there is no brief. | Built (PR #6) |
| Gap questions | Ask next: a live list of up to five questions for the gaps in what has been described (missing, vague or contradictory details), each with the gap it fills, plus up to two For-you questions when the brief is unclear. Not tuned to any kind of call. The assistant judges the gaps itself and removes a question once the call answers it. Refreshes after each utterance, on the Refresh button and with Opt-Q; questions can be dismissed; open ones go into the meeting note. | Built (PR #6) |
| Stay on screen until the note is done | With the assistant on, the app waits for Save or Discard on the note before it opens the meeting details. | Built (PR #1) |
| meetily-fork name | The window, dock, tray and notifications say meetily-fork, so it can sit next to an installed upstream Meetily. | Built (PR #4) |
| In-app updater off | Meetily's update prompt no longer appears, because it would install plain Meetily over the fork. Upstream updates arrive by merging. | Built (PR #4) |
| See the Zoom window | While recording, the assistant grabs the Zoom meeting window about once a second, keeps a picture only when it changes (the /watch scene rule), saves kept pictures full-size in the meeting folder's `zoom-frames/`, and sends new ones to Claude inside each turn: the newest one with a suggested answer or Explain, all new ones with Ask, Catch-up and the fuller check, and the call's slides with the note. A Settings switch, on by default, turns it off; a missing Screen Recording permission shows a line with a button to System Settings. A turn that fails with pictures is retried once without them. | Built (PR #9) |
| Answered questions kept | A question Joseph asks or the assistant suggests, once answered on the call or worked out by Joseph and the assistant, moves to an answered list with its answer instead of being removed, and goes into the meeting note under "Answered questions". The ask lanes reply with `DONE: <question> \| ANSWER: <answer> \| BY: call\|chat`; a For-you answer Joseph types moves its question there as "You answered". Joseph never ticks anything off. | Built (PR #16) |
| Say and Ask lanes | The assistant panel is two lanes under one brief bar. Say: the newest answer pinned at the top, then earlier answers and Joseph's own Ask, Explain and Catch-up replies newest first, with All / Answers / Mine filters. Ask: the open gap questions numbered, with a New tag on new ones, the For-you questions, and every answered question with its answer and how it was answered. One label, icon and colour per kind (blue Answer, violet To ask, green Answered, slate for Joseph's own chat). Every bullet shows; a pulsing dot and "Drafting" replace the amber border. | Built (PR #16) |
| Brief bar | The brief shows as two lines across both lanes, with Read all to open the whole brief in the Ask lane (the pinned answer never moves) and Edit to change it during the call. | Built (PR #16) |
| Resizable panel | Drag the panel's left edge (or focus it and use the arrow keys) to set its width, from 440 px up to the window less 420 px for the transcript; default 600 px, double-click resets it, and the width is remembered. The recording controls stay clear of the panel. | Built (PR #16) |
| Screen Recording line | With "See the Zoom window" on and no Screen Recording grant, an amber line under the panel header says "Can't see Zoom: Screen Recording is off." with an Allow button. It re-checks on focus, at recording start and every 30 s. | Built (PR #16) |
| Second Brain context | Every Claude turn the assistant makes (the trunk, suggested answers and the fuller check, Ask, Explain, Catch-up, Ask next, the note) carries a small startup context, the way a Claude Code session loads CLAUDE.md: the vault page index, the routing registry (where each department and repo lives), Joseph's profile, and a meeting rule (live call, read only, answer briefly, never start helpers or agents, never write anything). `--safe-mode` stays on, so nothing else loads. When the brief names a project or client, that project's vault page rides along too (up to 12,000 characters, cut at a heading), so the no-tools fast lane has it without reading files; a changed brief re-resolves the page on the next turn. Files are read when the session opens; a missing one is skipped with a log line. | Built (PR #15): pre-reading people pages not yet |
| Ask next, quick then checked | Ask next runs two lanes like the answer cards: a quick list from the fast model shows first, then a fuller list from the deep model, which may read the vault under ~/brain (read-only), replaces or corrects it. The panel shows Checking while the fuller list runs and Checked once it lands, and briefly highlights the questions it added or reworded. A quick list never overwrites a checked list that has heard as much of the call, and a checked list that heard less of the call than the quick one keeps the quick questions it never heard. | Built (PR #15) |
| Fast lane effort medium | The fast lane's default effort is medium instead of low; a migration moves a saved low to medium once. | Built (PR #15) |
| Test Mac add-on | Builds made by testenv/build-test-app.sh include an embedded WebDriver server so the user-mock agent can use the app in a throwaway test Mac. Builds Joseph installs never include it: the test build lands in `target/testenv/`, never in the release bundle path, and makes no DMG. | Built (PR #11) |
| Named icon buttons | The round record, stop, pause, resume and play buttons, the sidebar's record button, and the Ask box's send arrow and mic have accessible names (Start recording, Stop recording, Pause recording, Resume recording, Play recording, Recording in progress, Send question, Speak a question, Stop and submit), so the user-mock agent and screen readers can find them. The look is unchanged. | Built (PR #11) |
| Assistant history | What the assistant showed during a call (answer, Ask, explain and catch-up cards, and Ask next questions with their answers) is saved with the meeting when it is saved, with no prompt. A copy goes to `assistant.json` in the recording folder, and the meeting page has an Assistant tab beside the transcript with each item's call time. Joseph can delete a meeting's saved items, and deleting a meeting also removes its `assistant.json`. | Built (PR #17) |
| To do list | A live To do list in the assistant panel: what Joseph promised (You) and what the other side owes him (Them, with the person's name when the call says it). The Ask next run picks them up from the transcript, quick then checked, with no extra Claude call: TODO, TODO DONE and NOT TODO lines beside its questions. Joseph can also type one after `todo:` in the Ask box (Opt-T starts one in the app) and dismiss a wrong one. A to-do the call shows finished moves to Done by itself. The panel shows a one-line strip above Explain and Catch up with the counts and the newest to-do; clicking it opens a two-column drawer (You promised, They owe you) over the lower lanes. The to-dos are saved with the meeting (assistant history and `assistant.json`) and shown as a ledger at the top of the meeting's Assistant tab. Nothing is sent anywhere, and the vault note is unchanged. | Built (PR #18) |
| Manage assistant items | Every answer card, Ask and For-you question, answered question and to-do can be deleted: its x deletes one, and Select in the panel header (or on a past meeting's Assistant tab) gives checkboxes, Select all and Delete with a confirm. It works during the call, after Stop and on past meetings. A deleted item leaves the saved history, `assistant.json`, the note draft and a filed vault note; a delete on the Assistant tab also clears it from the live panel. A question dismissed with its x is no longer saved. | Built (PR #19) |
| Brief saved | The meeting brief is saved with the meeting (`meeting_assistant_meta`, `assistant.json`) and shown on its Assistant tab and in the vault note. | Built (PR #19) |
| Note filed under a project | The note bar suggests a vault project from the title, brief and transcript and lists every `Wiki/Projects` page plus No project. Save writes the note (Brief, the model's note, Answered questions and Q&A from the saved items, never to-dos), links it under the project page's `## Meetings`, and commits only those files. The Assistant tab shows where it was filed. | Built (PR #19) |
| Teams calls seen too | While "See the Zoom or Teams window" is on (the old "See the Zoom window" switch, same setting), the capture also finds a Microsoft Teams meeting window (`com.microsoft.teams2`, classic `com.microsoft.teams`, never the main window) when no Zoom meeting window is open, and keeps pictures by the same rule. Teams pictures go to `teams-frames/` in the meeting folder, Zoom's stay in `zoom-frames/`, and Claude sees them labelled "Teams window at". The test Mac has a Teams stand-in. | Built (PR #20) |
| Meeting named from the call window | At Stop, a meeting still under its automatic "Meeting ..." name takes the cleaned title of the Zoom or Teams meeting window the capture saw (" - Zoom" and " \| Microsoft Teams" dropped, generic titles like "Zoom Meeting" skipped). No title means the timestamp name stays; a name Joseph sets by hand always wins. The folder keeps its timestamp name. | Built (PR #20) |
| What was saved | Each meeting page shows its title, Brief and "What was saved: 10:04 to 10:47, 43 min, 181 pictures, 165 MB" (start, end, length, pictures in zoom-frames/ and teams-frames/, folder size). The sidebar shows totals above the list (meetings, hours, pictures, disk space) and each meeting's Brief under its name. Read-only, from `meeting_saved.rs`. | Built (PR #20) |
| Meeting detection | When a Zoom or Teams call starts, a macOS notification names the app ("Zoom meeting started", "Teams meeting started") with a Record button, and the app shows a card per call with "Record <app> meeting" and "Dismiss". Each app is tracked on its own, so two calls give two notifications. A call counts when the app's own process holds the microphone (Core Audio process list, ownership checked by the executable sitting inside the app bundle) and it shows a meeting window (Zoom: a meeting-titled window, never the home window; Teams: a meeting window, or any window while Teams was in front within 30 s of the mic turning on). Any doubt means no prompt. Nothing is prompted while recording, and a call seen during a recording is not prompted afterwards. Dismissing an app silences it for 30 minutes. The approach follows Fluid Voice, written fresh (Fluid Voice is GPL-3). | Built (PR #PRNUM) |
| Record one app's sound | A recording started from a detected call taps only that app's processes for system audio (a Core Audio process tap of the app's process objects, updated every 2 s as the app starts new helpers), plus the mic as before. A Call audio picker beside Start recording chooses All apps (default), Zoom only or Teams only for a manual start; while recording the controls say which. No choice means the global tap, as before. | Built (PR #PRNUM) |

## Upstream bug fixes

Bugs in upstream code fixed here. Each is a candidate to send upstream.

- **Recording arguments dropped (PR #1):** `recordingService.ts` sent snake_case keys that Tauri v2 ignores, so device and meeting names were lost.
- **Recording auto-started after relaunch (PR #1):** the `autoStartRecording` flag is now a short-lived timestamp in `SidebarProvider.tsx`.
- **RUST_LOG ignored (PR #1):** `main.rs` now sets a default only when the variable is unset.
- **Built-in mic test failed on some hardware (PR #5):** `device_detection.rs` no longer depends on the host machine.
- **Release app needed Homebrew onnxruntime (PR #10):** on a build Mac with Homebrew's onnxruntime, `ort-sys` linked that dylib by absolute path, so the app died at launch on a Mac without Homebrew. `LIBONNXRUNTIME_NO_PKG_CONFIG` in `.cargo/config.toml` makes it link pyke's prebuilt static build instead, so nothing extra ships in the bundle. Upstream has the same latent bug.
